Toda entrega já chega como carta que se entende

Proposta de mudança no tarefa_entregar e a régua de quando uma decisão sobe a você. Uma página; a implementação é outra tarefa, depois da sua escolha.

1. O problema de hoje

A carta mostra o que a tarefa guarda: o seu pedido no topo, o critério técnico, a nota de quem entregou e as provas cruas (saída de comando, link do GitHub). Nenhum desses campos foi escrito para você decidir. Por isso o pedido é ignorado, o link não explica, e decisões de verdade (trocar a conta ou esperar) viram “aceitar = troquei, rejeitar = esperamos”.

2. O que muda na entrega: um bloco “para o dono”

Campos novos no tarefa_entregar

paraODono: {
  titulo:   "Fase 2 da VPS: senhas e logins",   // nome humano, até 60 letras
  pergunta: "A VPS já tem todos os acessos. Aceito a fase 2?",
  resumo:   "As 6 checagens passaram. Sobrou uma ponta solta: …",
  opcoes: [                                     // 2 a 4
    { rotulo: "Aceitar com ressalva", efeito: "…", risco: "…",
      fecha: "aceita", recomendada: true },
    { rotulo: "Rejeitar", efeito: "…", risco: "…", fecha: "rejeitada" }
  ],
  porque: "tudo o que a fase pedia funcionou; …", // por que a recomendada
  risco:  "Senhas de verdade numa máquina na nuvem. …",
  visual: { prova: 1 }                          // ou { antes: 1, depois: 2 }
}

Detalhes técnicoscritério, provas de texto e link, ids
  • Uma decisão vira opções com nome. Escolher grava a opção (rótulo) no histórico, e a tarefa fecha como aceita ou rejeitada conforme o fecha da opção. Rejeitar continua pedindo motivo; uma opção de rejeitar pode já trazer o motivo pronto (“esperamos o limite voltar”).
  • Visual obrigatório quando muda algo que você vê (tela, fluxo, texto): print, ou antes e depois. Sem tela (VPS, conta), o visual pode ser um quadro de checagens desenhado pelo app a partir de uma lista curta (visual: { checagens: [{ nome, ok, frase }] }), como na carta da VPS.
  • Obrigatório só no que sobe a você (risco alto e a amostra do dia). No risco baixo que o Revisor aceita, o bloco é opcional; sem ele, a carta antiga continua valendo.
  • Guarda no código, não no prompt: o contrato recusa a entrega que sobe a você sem pergunta, sem ao menos 2 opcoes com efeito, sem exatamente 1 recomendada, ou sem visual quando há print. O campo novo no documento sobe o schemaVersion do ledger (o canal mais velho fica só lendo, como na regra do mindscape.json).

3. Nada de código à vista

Você é humano: cada coisa aparece pelo nome. O texto “para o dono” é recusado quando traz código, com a mensagem dizendo o que trocar:

Recusado no texto para vocêEscreva assim
t-1b6c1a95, place:4fd3…, session:1a6d…“Fase 2 da VPS: senhas e logins”, “Dev · VPS Homologações”
feat/homologacao-agentica-v1-13, hash 2a98f2f, PR #105“a versão de trabalho do plugin”, “a mudança que liberou o login do Google”
src/main/…/arquivo.ts, crases, saída de comandoo efeito para você; a saída vai para a prova

Tudo isso continua existindo, só que dentro de “Detalhes técnicos”, recolhido. Para os lugares, o app passa a mostrar o nome do lugar no quadro (ex.: “Dev · painel do Jobu”), nunca o id. Junto vem um titulo já no tarefa_criar, para a tarefa ter nome desde que nasce.

4. Quando uma decisão sobe a você, e quando não

Sobe (vira carta “Decisão sua”)

  1. Difícil de desfazer: main, repo público, apagar algo, credencial, conta, dinheiro.
  2. Toca outra pessoa ou algo de fora: o Bill, a Marta, Slack, um cliente, a Seazone.
  3. Gasta o que é seu: limite de conta, VPS, a sua hora.
  4. Muda a forma do que você vê e há 2 jeitos bons: sobe com protótipo, nunca com descrição.
  5. Contradiz o que você disse (pedido, CLAUDE.md, memória) ou fica fora do que você pediu.
  6. Risco alto pelo contrato (já é assim hoje).

Não sobe (o agente decide e registra)

  1. Só uma opção é defensável: decide e escreve o porquê na nota.
  2. Escolha técnica que se desfaz fácil e está dentro do pedido (nome, ordem, biblioteca já aprovada).
  3. A resposta já existe em CLAUDE.md, ADR, memória ou decisão sua anterior.
  4. Correção de bug com teste guardando.
  5. Risco baixo aceito pelo Revisor (você vê só a amostra do dia).

Teste antes de subir: se o agente não consegue escrever a pergunta numa frase, com 2 opções reais e uma recomendação, a decisão ainda não está pronta para você: ele volta e pensa mais.
